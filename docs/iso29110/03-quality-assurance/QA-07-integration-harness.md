## สภาพแวดล้อม

คำสั่ง `npm test` ใช้ตัวรัน `node --experimental-strip-types --test` บนเครื่องพัฒนา ไม่ได้ตั้ง `SUPABASE_URL` หรือ `SUPABASE_SERVICE_ROLE_KEY` ในเทส และไม่ได้เปิดฐานข้อมูล

เทสโทเคนใช้ชื่อตัวแปร `ISO_TEST_TOKEN_SECRET` และ `ISO_TEST_PASSWORD` ค่าในเทสเป็นค่าปลอมสำหรับรันครั้งนั้น ไม่ใช่รหัสของระบบจริง

## สิ่งที่ยังไม่ใช่การทดสอบรวมของงานจริง

สี่ข้อใน `handler-load.test.ts` พิสูจน์ว่าไฟล์เหล่านี้โหลดในตัวรันนี้ไม่ได้:

- `src/routes/api/public/production-intake.ts`
- `src/lib/features/scan.functions.ts`
- `src/lib/features/qc.functions.ts`
- `src/lib/features/packing.functions.ts`

สาเหตุคือไฟล์เหล่านั้น import ด้วยนามแฝง `@/` และผูกกับ `supabaseAdmin` ซึ่งเป็น service role ตัวรัน `node --test` ไม่มีตัวแปลงนามแฝงของ Vite จึงหยุดก่อนสร้างไคลเอนต์ฐานข้อมูล

เพราะเหตุนี้รอบนี้ยังไม่มีผล PASS ของพฤติกรรม API การบันทึกสแกน การบันทึกรายงาน QC หรือการบันทึกรายงานแพ็ค และไม่มีฐานข้อมูลจำลองที่ตัวจัดการคำขอเหล่านี้เขียนลงไป

## ทางที่ยังต้องให้คนอนุญาตก่อน

ถ้าจะให้เทสเรียกตัวจัดการคำขอจริงโดยไม่แตะฐานผลิต ต้องแยกจุดรับไคลเอนต์ฐานข้อมูลหรือส่งออกตัวตรวจที่ตอนนี้ปิดอยู่ในไฟล์คำขอ การเปลี่ยนนั้นยังไม่ทำ เพราะรอบนี้ห้ามเปลี่ยน business logic โดยไม่ได้รับอนุญาต
